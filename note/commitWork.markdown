# commitWork 的实现

## 初步了解 commitWork

1. commitWork 位于第二个阶段, 也就是提交阶段
2. 前面一个阶段(渲染阶段), 我们已经完成了 Fiber 节点的创建以及宿主节点的创建和绑定
3. 目前页面上还没有展示任何内容, 那是因为我们渲染阶段所有的操作都是在内存中进行进行的,
   页面上是无感知的.
4. commitWork 的作用就是将内存中的宿主节点, 提交给宿主环境进行渲染

## commitRoot 的实现

1. 如果当前是初始化 mount 阶段(而非更新阶段), 那么提交阶段要做的事情就很简单, 就是将
   Fiber 链表的头节点 HostRootFiber 这个节点对应的 child.stateNode 挂载到 FiberRoot 对应的 containerInfo 的容器上就可以了.
2. 但是如果是更新阶段, 需要考虑每个Fiber节点上的副作用, 以及如何将这些副作用影响到浏览器页面上. 这我们就需要分析副作用了
3. 首先需要检查 rootFiber 上是否存在副作用, 以及它的子树是否存在副作用
4. 存在副作用, 在 Fiber 上提交变更副作用
5. 提交变更副作用:
   1. 只要它或者它的子树存在副作用，就递归遍历它的子节点，然后为它的存在副作用子节点应用 mutation 副作用
   2. 应用 Placement(fiber 节点存在需要插入的副作用) 副作用
      1. 获取 Fiber 节点插入前对应的宿主兄弟节点（参照节点）
      2. 根据当前要插入的节点获取对应的宿主节点（当前节点如果是宿主节点直接执行后续插入）
      3. 执行插入操作，如果有参照节点，则插入到参照节点之前；如果没有，则插入到父节点末尾

## 获取 Fiber 节点插入前对应的宿主兄弟节点

参照节点特点：即将要插入的父宿主节点内原有的子节点

- 内部第一个循环：向上寻找有兄弟节点的节点（特点向上回溯）
  - 如果当前节点没有兄弟节点
    - 那就向上回溯，当前节点指向父节点
    - 如果当前节点是 rootFiber（根节点）或者它的父节点是（宿主父节点），那说明在这个节点之前没有宿主父节点内没有兄弟节点，所以直接返回 null
- 外部主循环：如果当前节点有兄弟节点，当前节点指向其兄弟节点
- 内部第二个循环：筛选宿主节点
  - 如果当前节点不是宿主节点 ，不满足我们要查找的要求，继续查找
    - 继续查找它的子节点，目的是为了找一个宿主节点，当前节点指向其子节点
    - 如果当前节点是即将要插入的节点，也不是我们要找的，我们要找的是父节点原有就有的子节点（这次可能是要更改）
- 外部主循环：发现宿主节点，并且是当前节点的兄弟节点
  - 如果是即将要插入的节点，也不是我们要找的，继续回到循环内向上或者向下查找
  - 如果不是即将要插入的节点，那这个节点就是我们要找的节点（苦苦寻求的兄弟节点终于找到了 ^_^ ）

## 根据当前要插入的节点获取对应的宿主节点

1. 这个就是链表向上回溯的过程
2. 从当前节点向上查找 return 节点, 只有是宿主节点或者根节点才返回
3. 如果到根节点了, 会直接插入到 FiberRoot 对应的 containerInfo 中
